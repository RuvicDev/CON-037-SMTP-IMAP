¿Qué es y para qué sirve?

El conector SMTP/IMAP permite que el agente de Ruvic envíe correos y lea/busque en una bandeja de entrada, con cualquier proveedor de correo — un buzón corporativo propio, Gmail, o Microsoft 365/Outlook.

Una vez configurado, puedes pedirle al agente cosas como:

  • "Envía un correo a este cliente con el reporte adjunto."
  • "¿Tengo correos sin leer del proveedor de facturación?"
  • "Busca el correo de ayer sobre el contrato y dime qué dice."

Operaciones soportadas:

OperaciónQué hace
email.send_emailEnvía un correo (texto y/o HTML)
email.search_emailsBusca en la bandeja con filtros (no leído, remitente, asunto, fecha)
email.get_emailObtiene el contenido completo de un correo puntual
Gmail y Outlook ya no aceptan contraseña Google desactivó la autenticación por contraseña para correo en marzo de 2025, y Microsoft hizo lo mismo el 30 de abril de 2026. Si vas a conectar Gmail o Microsoft 365, tienes que usar el modo OAuth2 correspondiente — el modo de usuario/contraseña solo funciona con servidores de correo propios u otros proveedores que aún lo permitan.

Prerrequisitos

  • Una cuenta de correo dedicada a esta integración — no uses tu buzón personal.
  • Si vas a usar Gmail: acceso a Google Cloud Console para crear credenciales OAuth2.
  • Si vas a usar Microsoft 365/Outlook: acceso a Microsoft Entra ID (Azure AD) para registrar una app, y confirmar que SMTP AUTH esté habilitado para ese buzón (Microsoft lo desactiva por defecto en cuentas nuevas).
  • Si vas a usar un servidor propio: los datos de SMTP/IMAP (host, puerto) que te dé el administrador del correo, y una contraseña de aplicación si el proveedor la exige.

Configuración en el fabricante

Camino A — Gmail / Google Workspace (OAuth2)

  1. Crea (o usa) un proyecto en Google Cloud Console — console.cloud.google.com.
  2. Habilita la Gmail API para ese proyecto ("APIs & Services" → "Enable APIs and Services" → busca "Gmail API").
  3. Crea credenciales OAuth 2.0 ("Credentials" → "Create Credentials" → "OAuth client ID"), tipo "Web application", agregando la Redirect URI que te indique Ruvic al configurar el conector.
  4. Copia el Client ID y Client Secret generados — los vas a necesitar en la sección de Configuración en Ruvic.
  5. Si el proyecto está en modo "Testing" en la pantalla de consentimiento OAuth, agrega la cuenta de Gmail que vas a usar como "Test user", o publica la app si necesitas usar cualquier cuenta.

Camino B — Microsoft 365 / Outlook (OAuth2)

  1. Registra una app en Microsoft Entra admin center → "App registrations" → "New registration".
  2. Agrega la Redirect URI que te indique Ruvic, en la sección "Authentication".
  3. Crea un Client Secret en "Certificates & secrets" — cópialo de inmediato, solo se muestra una vez.
  4. Otorga los permisos de API ("API permissions" → "Add a permission" → "APIs my organization uses" → busca "Office 365 Exchange Online") con los scopes SMTP.Send e IMAP.AccessAsUser.All.
  5. Confirma que SMTP AUTH esté habilitado para el buzón específico — un administrador puede verificarlo/activarlo desde el Centro de administración de Exchange o con PowerShell (Set-CASMailbox -SmtpClientAuthenticationDisabled $false).

Camino C — Servidor de correo propio (usuario/contraseña)

  1. Pide al administrador del correo los datos de conexión: host y puerto de SMTP, host y puerto de IMAP.
  2. Genera una contraseña de aplicación si el proveedor la exige (algunos paneles de hosting como cPanel la llaman así, o simplemente usan la contraseña normal de la cuenta).
  3. Confirma que la cuenta tenga SMTP e IMAP habilitados — algunos proveedores los desactivan por defecto para cuentas nuevas.

Permisos requeridos

ModoAlcance otorgado
Gmail (OAuth2)Scope https://mail.google.com/ — acceso completo de correo (enviar y leer), sin acceso a Drive, Calendar, ni otros servicios de Google
Microsoft (OAuth2)Scopes SMTP.Send e IMAP.AccessAsUser.All — solo correo, sin acceso a OneDrive, Calendar, ni Teams
Contraseña (servidor propio)El alcance que tenga la cuenta de correo configurada en el servidor — usa una cuenta dedicada, no una cuenta con privilegios administrativos del correo

Configuración en Ruvic

Entra a Settings → Conectores, busca la tarjeta SMTP / IMAP y pulsa Configurar. Elige el modo según tu proveedor:

ModoCuándo usarlo
Usuario y contraseñaServidor de correo propio, o proveedores que todavía permiten contraseña
Gmail / Google Workspace (OAuth2)Obligatorio para cualquier cuenta de Gmail
Microsoft 365 / Outlook (OAuth2)Obligatorio para cualquier cuenta de Outlook/Microsoft 365

Completa los campos del modo elegido con lo que obtuviste en la sección anterior, y pulsa Probar conexión.

Verificación

  1. Test de conexión exitoso. El botón Probar conexión debe responder: "Conexión exitosa a [servidor IMAP] (modo: ...)".
  2. Prueba mínima con el agente. Pide algo de solo lectura primero:
    "¿Tengo correos sin leer?"
  3. Prueba de envío (opcional, con cuidado). Pide un envío de bajo riesgo, por ejemplo a tu propia cuenta:
    "Envíame un correo de prueba a mí mismo."

Solución de problemas

Mensaje / síntomaCausa probable y solución
"Autenticación SMTP/IMAP fallida" con Gmail o OutlookEstás usando el modo de contraseña con un proveedor que ya no lo acepta. Cambia al modo OAuth2 correspondiente.
"550 5.7.30 Basic authentication is not supported" (Microsoft)Confirma que uses el modo OAuth2 Microsoft, no contraseña — este es el mensaje exacto que da Microsoft cuando se intenta con contraseña.
"No se pudo renovar el token OAuth2..." (HTTP 400/401)La autorización fue revocada, o el Client Secret cambió. Vuelve a autorizar el conector desde Settings → Conectores.
"No se pudo conectar..." (timeout/red)Verifica el host/puerto configurados (modo contraseña), o que no haya un firewall bloqueando los puertos 587/993.
SMTP AUTH deshabilitado (Microsoft)Pide a un administrador de Microsoft 365 que habilite SMTP AUTH para ese buzón específico — viene desactivado por defecto en cuentas nuevas.

Preguntas frecuentes y notas de seguridad

¿Por qué no puedo simplemente usar mi contraseña de Gmail?

Porque Google la desactivó para este propósito en marzo de 2025 — es una decisión de seguridad de Google, no una limitación de este conector. El reemplazo es OAuth2.

¿El conector puede leer/enviar cualquier correo de mi cuenta?

Solo dentro de los scopes otorgados (correo), y solo lo que el agente le pida explícitamente hacer — no hay un acceso "de fondo" indefinido más allá de las llamadas que se ejecuten.

¿Dónde quedan guardadas las credenciales?

Como secreto en el almacén de credenciales de la plataforma. La interfaz nunca vuelve a mostrarlas.

Rotación de credenciales

Para OAuth2, la plataforma renueva el token automáticamente — solo necesitas re-autorizar si la autorización se revoca manualmente. Para el modo de contraseña, rota la contraseña de aplicación periódicamente según la política de tu proveedor.

Buenas prácticas Usa una cuenta de correo dedicada a esta integración, no tu buzón personal; en OAuth2, otorga solo los scopes de correo (no marques permisos adicionales de Calendar/Drive/OneDrive al crear las credenciales); y confirma con el usuario antes de que el agente envíe correos a múltiples destinatarios.
